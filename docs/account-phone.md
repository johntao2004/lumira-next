# 账号手机号验证

宿主初始化基线 `B52__platform_initialization.sql` 提供手机号绑定的最终表结构和唯一索引；绑定本身不改变登录方式。入口位于账号设置的“账号安全”页，通过独立弹层操作。后端入口为 `GET /api/account/phone`、`POST /api/account/phone/request` 和 `POST /api/account/phone/confirm`，均要求已登录、CSRF 和当前账号权限。

## 请求流程

1. 客户端读取当前绑定状态和版本。
2. 请求验证码时提交版本、手机号、当前密码和 locale。服务端先验证当前密码，再将手机号规范化为 E.164（去除空格、连字符和括号），检查短信配置和加密密钥。
3. `AccountPhoneStore` 在同一事务中锁定账号行，写入 pending phone、账号绑定的 HMAC 验证码摘要、当前安全策略配置的过期时间、请求计数和版本；默认有效期为 600 秒。`SmsDeliveryStore` 同事务写入加密短信任务。供应商未配置、密码错误或版本过期时不会留下验证码半成品。
4. 确认时只提交验证码。服务端比较摘要并按当前安全策略限制失败次数；成功后把 pending phone 提升为 verified phone、清空 token/过期字段并递增版本，验证码不可再次使用。

验证码为六位数字并保留前导零，以兼容国内云短信验证码模板。摘要使用部署密钥与账号 ID 作 HMAC-SHA256，数据库中不存明文，也不能仅凭数据库枚举短验证码。密钥轮换期间保留旧 key 可验证未过期验证码；历史长 token 继续有效至过期。模板 `{minutes}` 从实际安全策略有效期生成，不固定写死十分钟。

## 限制与安全

- 手机号必须符合 `+[国家码][号码]`，长度为 7–15 位数字；数据库唯一约束阻止跨账号重复绑定。
- 同一账号至少按当前安全策略的冷却时间间隔请求、每日不超过配置上限；独立 `phone-verify` 限流器限制请求和确认频率。
- 新密码最多 256 UTF-8 字节并使用版本化 Argon2id；历史 BCrypt 摘要仍可读取，但超过其 72 字节遗留边界的候选密码会被拒绝以避免截断歧义。密码、验证码和短信正文不会写入日志或返回结构，完整手机号只在当前账号的状态响应中返回。
- 失败确认会持久化失败次数；过期、超过配置失败上限、错误 token 和跨账号状态均返回受控本地化错误。

账号手机号浏览器回归覆盖未配置短信服务时的 503、错误后的密码清理、请求/确认控件、刷新状态、桌面和 390px 抽屉边界。当前未把手机号作为登录因子，也未宣称外部短信收件箱或生产供应商送达已验收。
