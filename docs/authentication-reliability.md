# 认证与角色功能的可靠性验收

本文补充[实施计划](role-authentication-plan.md)中的性能、可用性和故障验收要求。它定义实施约束与证据要求，不表示部署已经达到生产高可用。

## 数据与并发

注册、验证码、OAuth 尝试、CAPTCHA proof、MFA 恢复和角色预览使用共享 PostgreSQL 状态。一次性消费以事务和唯一状态转换裁决；节点内缓存不能成为授权依据。失败计数必须提交，接口随后再返回错误；异常不能回滚失败计数而让错误尝试无限重复。

主凭据与 MFA 凭据采用独立的修订。它们不同于业务资料版本，也不同于全局或角色策略修订。验证所得证据绑定当时的凭据修订，完成认证和每次已登录请求重新校验；旧会话不能通过补写最新修订复活。名称、显示资料或 Passkey 签名计数变化不视为凭据替换。

宿主初始化基线 `B52__platform_initialization.sql` 直接提供账号级主凭据与二次因素修订，以及 `platform_passkey_challenge` 中的主凭据修订快照。认证证据均按当前最终结构绑定修订值。

策略写持有短排他锁，认证读取及账号级凭据变更持有匹配的共享锁，再取账号行锁。账号之间的资料或凭据操作不能全部使用全局排他锁。默认角色变更、角色停用或修改与注册创建遵守同一锁顺序。角色成员可达性用批量关系查询检查，不在全局锁内逐账号查询策略。

网络交换、外部 CAPTCHA 校验和投递不持有数据库长事务。先认领操作，网络调用有总超时和响应上限，再用短事务核验状态、修订和期限。超时、取消、重复回调、提供方故障都不能降级放行。队列接受、外部渠道接受和用户实际收到是三个不同事实。

网络总超时覆盖响应正文接收，不能仅在读响应头时截止；超量、慢正文和线程中断均需取消交换并释放资源。JDK25提供[有界响应处理](https://docs.oracle.com/en/java/javase/25/docs/api/java.net.http/java/net/http/HttpResponse.BodyHandlers.html)，流式返回响应并不意味着正文已经接收完整。连续 OAuth 交换共享同一个尝试的网络预算。

公开流程的独立提交限流在业务事务之外执行。不得先占用业务连接和行锁，再为限流开启第二条连接的嵌套事务；并发达到连接池上限时也必须有界失败或正常完成。密码哈希在不持业务连接和锁的准备段执行，并限制并发和重复计算；可纠正的表单错误、策略版本冲突与已成功幂等重放分别处理，不能因重试限制使合法恢复路径失效。

挑战与过期记录有索引及有界批次清理。公开字段投影和表单正文遵守[自定义字段](custom-field-placement.md)的上限，不加载完整大字典后再截断。公开页按需加载第三方 SDK；后台保持现有懒加载和统一表单组件。

## 插件与多实例

共享 HTTP 会话不意味着插件运行时已支持多实例。当前插件是节点内加载图，发布新多实例模式前必须处理以下约束：

- 节点启动不得把另一存活节点的插件操作置为失败。
- 同一部署的节点必须使用同一经核验的插件图、包摘要和兼容迁移。
- 节点缺包、加载失败或图修订不一致时 readiness 必须失败，不能接收认证流量后才发现 MFA 提供方缺失。
- 生产多实例模式采用固定插件图时，在服务端拒绝在线导入、安装、启停、卸载及旁路模块开关。同一图的节点可逐个替换；更换插件图前须排空旧节点，再发布整套图。当前实现不支持不同插件图并行服务，新图发布的维护窗口须纳入实际可用性目标。单实例开发保留现有在线生命周期。
- 不允许用节点本地 Map、本地文件或单进程执行器证明跨节点 challenge、角色预览或投递租约正确。

宿主全局数据库按 `B52__platform_initialization.sql` 初始化为当前结构；插件包及其独立数据库变更与固定插件图一并发布。滚动发布期间旧节点不支持的新能力保持关闭，直到全部节点完成切换。

## 验收分层

| 层面 | 需要的证据 |
| --- | --- |
| 源码与构建 | 模块依赖无环、路由权限覆盖、JDK25/Node24 的测试与生产构建；镜像构建独立记录 |
| 数据库与状态机 | 证明单次消费、幂等回执、完整回滚、并发唯一性、凭据失效、用途隔离、默认角色引用保护 |
| 浏览器 | 指定交互、刷新恢复、桌面与390px、明暗主题、八语言、错误反馈、无横向溢出 |
| 外部服务 | 真实邮件/短信收件、微信网站应用授权、CAPTCHA主挑战及语音挑战；测试适配器另列 |
| 节点切换 | 两节点共享会话和挑战，在切换或停止一个节点后继续受限流程，旧 proof 与旧 revision 仍被拒绝 |
| 故障 | 提供方超时/错误、数据库不可用、队列租约中断、插件加载失败，全部安全失败且有可定位错误 |
| 生产容灾 | 实际负载均衡、数据库故障切换、备份/PITR及恢复演练；本地读取压测不能替代 |

性能对比使用同一隔离数据库、同一接口和硬件，记录预热、并发、时长、请求数、错误率及 p50/p95/p99。认证读取与密码计算分别测量，不用一个冷启动登录耗时代表容量。旧版读取基准仅存于临时验收材料；新策略出现回退时先定位 SQL、连接池和锁等待，再调整，不以延迟策略失效来换取数字。

生产 SLO、RPO 和 RTO 需结合实际部署及容量制定并演练。单机测试通过只证明该测试条件下的行为，不能据此承诺网站在任何故障下持续可用。

默认未配置不是事务异常。供应商就绪探测必须以正常返回值表示关闭、缺密钥或缺模板，不能调用会在 Spring 事务边界抛异常的严格加载方法，再在外层捕获并返回 false；这种写法会留下 rollback-only 标记，使正常密码登录及权限读取失败。探测复用当前连接，不采用额外 REQUIRES_NEW 连接来掩盖问题；数据库故障继续按实际基础设施错误处理。

## 本地实现与生产交付边界

当前实现提供固定插件图、共享数据库节点租约、节点自身 readiness 检查及认证流量准入；图不匹配或未批准时拒绝业务流量，liveness 保持独立。在线生命周期在固定图模式下由服务端拒绝，包括只有一个存活节点时。单实例开发模式仍保留在线模块管理。部署步骤及整套图更新的排空要求见[插件运行](plugins.md)。

本地隔离验收覆盖两个应用节点的共享会话、跨节点受限 MFA 与恢复、角色预览及一次性资源票据；也覆盖停止一个节点、审批图暂时失效后的拒绝与恢复。这里只证明应用层在相同图、共享数据库与密钥条件下的行为。实际负载均衡、数据库故障切换、镜像构建及备份恢复演练仍需生产环境验收。可复现原始证据与性能数字保存在 `.runtime/role-authentication/acceptance.md`，不将临时压测数值当作长期容量承诺。
