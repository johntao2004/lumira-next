# 前端编码规范与版本适配

## 固定参考来源

参考 Alibaba f2e-spec 的 [React规范](https://github.com/alibaba/f2e-spec/blob/beb1ac899ea6dab206331263bbcdcad8f8fe336e/docs/coding/react.md)。本次核对仓库版本 `beb1ac899ea6dab206331263bbcdcad8f8fe336e`；该文件最近修改提交 `57bd6955ef6eef545ffc302130f04e352f260b61`（2024-02-11），文件 blob `d43ee7cf771351c01ae8b5c78b4d396e3b40a8a5`。这里总结适用规则，不复制原文示例。

项目实际使用 React 19.2.8、TypeScript 7.0.2、Umi 4.7.20 和自动 JSX 转换。参考文档包含旧版本示例，必须按下面的适配编码。

## 必须遵守

- 组件职责明确，公共运行时不能反向引用宿主业务装配；业务组合、共享基础能力和功能页面分别在 app/platform/features。
- JSX 层级清楚；children 使用嵌套内容；列表 key 表达稳定身份，不能以索引代替会变动条目的身份。
- Hooks 只在组件或自定义 Hook 顶层调用。依赖必须表达闭包实际使用的稳定值，不能为消除告警盲加每次新建的对象/函数，引发重复登录、请求或注册。
- 不直接修改 state/props。异步工作绑定账号代际与生命周期，换号、撤权和卸载时取消旧任务；客户端可见性不替代服务器权限。
- 交互元素具备键盘与可访问名称；图片按语义提供替代文本；保留已有输出净化，不因存在 innerHTML 就删除经过审核的富文本能力。
- `refetch` 等稳定函数解构后作为依赖；导航数组需要按内容触发时，使用明确的稳定键并在 effect 内还原所需值，避免依赖数组里隐藏表达式。
- 每处核心职责/重要逻辑注释简短中英对应；不写与当前客户端模型不符的 SSR 说明。

## 不照搬的旧示例

- 根挂载由 Umi 管理，不新加 ReactDOM.render、findDOMNode、字符串 ref 或 UNSAFE 生命周期。
- 使用 TypeScript props 类型和参数默认值；不为函数组件新增旧式 propTypes/defaultProps。
- 自动 JSX 转换下不要求每个 JSX 文件仅为语法导入 React。
- class 组件方法排序不套到函数组件。原规范允许同一文件存在多个职责相关的函数组件，不为“一个组件一个文件”机械拆散私有辅助组件。
- Hook 依赖告警需要逐条判断；认证/MFA/CAPTCHA 的 epoch/generation 护栏不能因风格整理而移除。

## 验收边界

现有命名、重复检测、双语核心契约检查、TypeScript、测试与生产构建必须通过。React/JSX/Hooks专项门禁以仓库实际脚本为准；告警、手工审查和实际浏览器验收分别记录，不能将静态诊断未报错说成所有界面已验证。

本轮审查发现的依赖告警包含设计上稳定的值与尚需分类的历史闭包，不等同于同等数量的已确认功能缺陷。所有新改核心组件需解释依赖及资源清理；旧告警不能作为新代码豁免依据。

`pnpm check:react` 是当前可执行专项门禁，并纳入 `check:quality` 与 CI。Hooks 调用规则、缺失 key、重复属性、字符串 ref 等结构错误阻断；历史 exhaustive-deps、索引 key 和 JSX 间距以告警呈现，必须逐项审查而非盲目自动修复。该门禁不包含完整 React 19 移除 API 清单和自动 a11y 审计，真实键盘与屏幕阅读器体验仍须浏览器验收。

26条依赖诊断的逐项判断及剩余历史问题见[依赖审查记录](react-dependency-review.md)，保留有效失效信号和认证代际护栏。
