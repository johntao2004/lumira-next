# 后端编码规范与适用差异

## 已核验来源

用户附件：《Java 开发手册》嵩山版，1.7.0，2020-08-03。原件63页；封面已目视检查，版本见PDF第55页（印刷52/59），全文已提取。以下页码统一使用PDF物理页码，括号为印刷页码。本文是本项目适用建议，不宣称仓库已逐条合规。

来源为项目维护者提供的该版本附件；仅总结与本项目相关的规则，不转载手册全文。

## 必须记录的适用差异

1. PostgreSQL不是MySQL。41–46页中的unsigned tinyint、自动递增bigint、datetime、索引前缀、IFNULL、MyBatis语法不直接采用。保留已验证的boolean/UUID/timestamptz/JDBC/PG约束；不能为命名规则重写已应用B52或插件迁移。金额继续保持精确数值或整分，不能改浮点。
2. 42页“超过三个表禁止join”、固定表容量阈值属于该手册实践限制，不作为本项目机械规则。按PG执行计划、索引、延迟与容量证据决策，不能因此增加应用层N+1。
3. 20页线程池建议针对当时平台线程背景。JDK25虚拟线程/结构化或受管理任务应分别评审并发上限、资源占用与取消；不通过“禁止Executors文本”误删已受控实现，也不自动将所有工作换虚拟线程。
4. 27页创建者/创建日期不能编造。新文件可记录真实信息，旧文件作者由版本历史核验；项目可明确采用Git追溯而不机械填充虚假@author。用户双语要求优先于手册推荐中文单语。
5. 48页要求二方库首版1.0.0，而本轮0.1.0-alpha.1是明确未稳定的预发布。应在docs写出差异、兼容承诺及发行门槛，不能仅改版本号伪装稳定。上线制品禁止SNAPSHOT与可覆盖发布，正式发行另验。
6. 49页接口枚举返回限制不可无评估破坏现有API；新增值的序列化和未知值处理应有兼容测试，已发布契约变更按版本窗口处理。
7. 35页固定日志路径、15天/六个月留存不能直接当成当下合规结论；容器日志由采集策略管理，数据类别、地区及保留政策另确认。不能照手册示例记录全部输入以泄漏秘密。
8. 49–50页TCP参数、JVM等值堆等不能自动应用到当前容器。保留资源隔离，生产负载证据驱动调整；网络安全设置仍需相应授权。
9. 34页catch Throwable用于插件边界清理可以有据，但不得全局吞Error并报告成功。清理后保留并传播主失败，恢复失败保持拒绝服务。
10. 47页层次是职责指导，不要求每个功能都增加Manager/BO/VO，也不要求微服务。维持本项目七区及同进程支撑层。

## 验收与持续维护

公开 SDK 的类及抽象方法须提供简洁中英对应职责、参数、返回、失败与调用约束。必要参数、返回和异常优先使用有信息量的Javadoc标签，但不为无参void方法编造return，也不机械复述参数名。具体方法没有的异常或空值保证不得编造。核心清单见 `../core-file-inventory.json`；文件头检查不能替代逐方法和语义审查。

独立应用构建、私有类编译失败和样例升级恢复由 `scripts/verify-independent-app.py` 验证；宿主权限、事件事务、插件恢复由真实 PostgreSQL 测试覆盖。Office 隔离解析、浏览器和实际生产部署分别验收，未关闭项见 `../production-readiness.md`。本项目不宣称执行过全仓 P3C 扫描或满足手册所有条款。
