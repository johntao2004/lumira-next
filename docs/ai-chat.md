# AI 聊天输入与附件

助手回复使用 Ant Design X Markdown 的 GFM 解析与官方 light / dark 主题，随全站主题切换。标题、列表、引用、表格、链接和行内代码使用官方样式；代码块映射到 Ant Design X CodeHighlighter，提供语言标记、语法高亮与复制。长表格和长代码在消息内横向滚动，任务列表只显示不可编辑的复选框。原始 HTML 转义展示，远程图片不加载。

用户查询支持每轮最多 4 条只读 `users_search` 调用。后端先验证整批参数，再按当前账号的数据权限查询；相同查询条件只执行一次，重叠用户按记录 ID 合并。每个条件最多返回 10 条记录，合并结果保留在用户查询表格，回复以 Markdown 表格列出前 10 条，并在转义后限制长度，避免超过后续会话的 5000 字符上限。姓名、账号和查询条件中的 Markdown 符号按文本转义，换行不产生额外表格行。列举用户使用空的 `search` 字符串；本轮查询完成后直接返回结果，不追加模型调用。

每轮账号变更仍只生成一个待确认草案。多条变更、查询与变更混合、未知工具或超出调用数量的整批请求会在执行前拒绝；管理员确认、权限检查和取消流程继续生效。

修改或删除草案前，后端通过用户目录权限路径读取目标账号，并将 `id`、账号名、显示名、启用状态和记录版本保存在草案的独立 `target` 字段中；模型文本不作为目标身份。确认时会重新授权并读取目标，任何字段或版本变化、目标不可见、或旧草案缺少快照都会拒绝执行。创建草案没有目标快照，仍要求管理员在确认表单输入初始密码。

供应商传输使用单调总截止、主动取消和最多 32 个无队列工作槽；饱和请求会快速失败。目的地资料及密钥在短 `REPEATABLE_READ` 快照中读取，事务释放后才进行网络请求。Office 解析预算边界和 OLE2 格式的限制见[文件预览说明](file-preview.md)。

模型服务和模型选择位于 Ant Design X Sender 的底部工具栏，附件卡片位于 Sender.Header。点击回形针选择文件，也支持向输入框拖放文件或粘贴文件。每条消息最多 4 个附件，每个最多 5 MiB；仅有附件时可以直接发送。

附件复用 `/api/account/files` 上传、账号隔离、CSRF、上传限流和文件配额。上传完成后调用 `GET /api/platform/ai/attachments/{id}` 验证文件并返回名称、大小、图片标记和截断标记。移除输入框中的卡片只取消该消息的附件引用；已上传文件仍保存在个人文件中心，可在那里移入回收站。

`POST /api/platform/ai/chat` 的每条消息可选传入 `attachmentIds` UUID 数组。服务端只允许 user 消息携带附件，并重新检查文件归属和 READY 状态。客户端不能通过请求指定远程附件 URL、提取内容或识图能力。文件模块通过 `AiAttachmentPort` 暴露受限读取契约，AI 模块不直接访问文件存储。

PDF、DOC、DOCX、TXT、Markdown、CSV、JSON 和 LOG 在服务端提取为文本；每个文档截取前 20000 个 UTF-16 单元，保留完整 Unicode 字符，PDF 最多读取前 100 页。提取文本再次经过账号内容策略检查。空文本、扫描 PDF、加密或损坏的文档明确报错；不提供 OCR。模型提示区分用户请求与附件参考内容，附件不构成系统指令或账号变更授权。

PNG、JPEG 在服务端验证实际像素、限制尺寸、剥离元数据，并缩放至最长边最多 1536 像素；发送使用 OpenAI 兼容协议的 `image_url` 内容片段和受控 PNG data URL。仅所选模型的模型目录明确声明 `input_modalities` 包含 `image` 时允许发送；兼容 OpenRouter `architecture.input_modalities`，不会从供应商级 VISION 配置推断模型能力。文本模型仍能处理提取后的文档。

每次请求最多携带 12 个附件引用、4 张图片和 80000 个提取文本单元；超过上限要求减少附件或新建会话。附件引用与名称等元数据随账号隔离的浏览器会话历史保存，文件字节和 data URL 不写入 localStorage。刷新和重新生成时重新从服务端读取文件；移入回收站的文件不能继续发送。取消生成会恢复原消息和附件草稿。
