# 账号邮箱验证

当前已实现并加载请求/确认接口、八语言纯文本邮件模板及个人资料中的账号邮箱抽屉。账号资料接口没有直接写入已验证邮箱的入口。

前端复用 AsyncButton、QueryFailure、API 客户端和多语言系统。邮箱在独立表单中请求/确认，不提交基本资料的未保存输入；每次请求后清空当前密码，关闭窗口时清空密码和验证码。提交和状态刷新期间禁用关闭入口；重新打开和窗口获焦时重新查询邮箱状态，避免全局缓存新鲜期隐藏变化。界面区分入队提示与已验证结果。

浏览器回归通过发信失败反馈与密码清空、保留基本资料未保存值、真实后端确认、页面刷新后持久化以及 390px 边界。发信请求被拦截，确认使用独立账号的数据库挑战夹具，因此不代表真实收件箱端到端验收；没有发送外部邮件。测试已加入标准浏览器/CI 入口。首次回归发现关闭按钮未反映忙碌状态和重新打开沿用缓存，两处已修复并复跑通过。

GET /api/account/email 返回当前账号的已验证/待验证状态及版本。POST /api/account/email/request 接受 version、email、currentPassword 和 locale，要求登录与 CSRF，并再次校验当前密码。服务先检查 SMTP 已启用且凭据可用，再将待验证记录、加密邮件队列任务和审计原子提交；202 仅表示已入队，不代表 SMTP 接受或收件成功。原始验证码不出现在响应中。

POST /api/account/email/confirm 接受 token，成功返回 204，无效返回 400，邮箱占用返回 409。失败次数在服务事务提交后才转换成错误响应。请求与确认共用每账号每分钟十次的独立提交限流，错误密码等失败不能回滚该计数。

V25 将已验证邮箱与待验证邮箱分开。发起新验证不改变已验证邮箱；成功确认才原子替换邮箱、记录时间、清除待验证令牌并增加版本。已验证邮箱采用不区分大小写的唯一性规则，避免多个账号绑定同一个地址。账号删除时清理其绑定和待验证记录。

VerificationToken 使用 32 字节随机值，URL 安全编码后 43 字符，只保存 SHA-256 摘要。令牌与账号的当前挑战绑定，在当前安全策略配置的有效期内一次使用（默认 600 秒）；新请求替换旧挑战。不要将原始令牌返回状态接口或写入日志。后续确认页面需要登录并显式提交，不能通过页面 GET 自动消费验证链接。

AccountEmailStore 对同一账号加行锁，发起请求检查版本，按当前安全策略限制冷却时间和每日请求上限。每日窗口使用数据库 CURRENT_DATE。失败确认次数必须提交，所以 confirm 返回 false 而非抛出异常；达到配置失败上限后当前挑战不能再成功。过期或其他账号的令牌不会确认邮箱。

AccountEmailService 和 AccountEmailController 已提供当前账号授权、CSRF、SMTP 配置检查和同事务入队/审计。并不在发起请求时测试网络连接；传输结果由邮件任务记录。邮箱唯一性冲突保留原绑定和待验证状态。前端已提供当前密码输入、确认入口及错误反馈。

真实 PostgreSQL 回归覆盖待验证与已验证分离、一次使用、过期、失败上限、替换、频率和版本限制、调用方事务回滚、并发确认只成功一次、跨账号拒绝、大小写唯一性及账号删除清理。测试不发送邮件。

功能专项和真实 HTTP 回归均通过；当前完整 clean verify 为 242 项，零失败/错误/跳过。HTTP 回归覆盖状态字段、匿名/CSRF 拒绝、错误密码、账号绑定、失败次数持久化、一次确认、唯一冲突、失败上限和限流 429；独立账号已清理。正向确认使用数据库待验证夹具，未验证真实收件箱或前端到外部邮箱的端到端送达。验证码有效期、冷却、每日配额和失败上限读取 `/dashboard/security` 的当前策略。
