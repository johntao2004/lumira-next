# 数据格式与校验约定

平台在 HTTP 入口检查数据类型，在业务服务检查字段格式、范围和关联条件；前端复用相同规则，尽早显示错误。数据库约束继续承担最终一致性保护。新增字段应同时声明类型、空值语义、长度单位和有效范围。

## HTTP 数据类型

MVC JSON 请求使用 `RequestJsonConfiguration` 的专用读取器。整数必须使用 JSON 整数，布尔必须使用 `true` 或 `false`，文本必须使用字符串，枚举使用约定名称。版本、排序、超时等整数不接受 `1.5`、`1.0` 或 `"1"`；布尔不接受 `1` 或 `"false"`。整数溢出、枚举序号、重复 JSON 属性及完整对象后拼接其他 JSON 值均返回 400 `invalidRequest`。

允许小数的字段继续接收 JSON 数字，例如水印透明度。自定义资料中的 NUMBER 按既有接口传递十进制字符串，避免 JavaScript 浮点转换损失精度。可选字段和新建记录的缺省值仍由各业务契约决定，不统一把省略字段视为错误。

专用读取器不改变响应序列化、数据库 JSON 的读取器或第三方供应商客户端。表单编码的登录参数、文件上传和第三方回调继续使用各自入口的校验规则。

`RequestTextAdvice` 在控制器执行前拒绝已绑定且可序列化的 JSON 文本、对象键和嵌套集合中的 NUL（U+0000），避免 PostgreSQL 文本写入失败。未知且未绑定的 JSON 属性不在此检查范围内。多行内容仍允许正常换行和制表符；SMTP 等单行协议字段保留自己的控制字符限制。

## 分页与筛选

| 参数 | 规则 |
| --- | --- |
| page | 正整数 |
| pageSize | 1 至 100 |
| search | 去除首尾空白后最多 100 个 UTF-16 单元，无 NUL |
| filters 和 filterModes | 各最多 40 项，不接受 null 键值 |
| 筛选名称 | `[A-Za-z][A-Za-z0-9_.-]{0,100}` |
| 筛选值 | 最多 512 个 UTF-16 单元，无 NUL |
| 筛选模式 | contains、exact、range |

`PageFilterSql` 的列名来自 Repository 白名单。时间范围须另外通过三参 `build(page, columns, timeColumns)` 显式声明日期列；两参版本不允许范围筛选。文本和布尔字段不能使用时间范围。

日期边界支持 ISO 带偏移时间、ISO 本地时间、`yyyy-MM-dd HH:mm:ss` 和 `yyyy-MM-dd`。带偏移时间规范为 UTC；本地时间沿用数据库会话时区。非法日历日期、超范围时间、反向区间及同一区间混用有时区和无时区边界均返回 400。单边区间保持有效，空边界不加条件。

## 资料与常用表单

| 数据 | 规则与入口 |
| --- | --- |
| 自定义资料必填 | 按服务端 `String.strip()` 的空白规则判断；数值 0 有效，可选空值可以清除 |
| TEXT 与普通资料值 | 去除首尾空白后最多 200 个 UTF-16 单元 |
| TEXTAREA | 去除首尾空白后最多 2000 个 UTF-16 单元 |
| NUMBER | `-?(0\|[1-9][0-9]*)(\.[0-9]+)?`，有效数字最多 30 位，小数最多 10 位，不接受指数、NaN、Infinity 或多余前导零 |
| DATE | `yyyy-MM-dd` 且为真实日历日期，含闰年检查 |
| SELECT | 静态选项必须匹配候选值；字典选择传递 UUID，授权与可选性由服务端确认 |
| 排序、权重、保留期、端口及超时 | Form 规则声明整数和业务范围，不能仅依赖控件的 min、max、precision |
| SMTP | ASCII 主机标签和邮箱，允许协议契约中的单标签域；端口 1 至 65535；主机 253、邮箱 254、用户名 320、显示名 120 个 UTF-16 单元，拒绝控制字符；网络目的地继续由服务端检查 |
| 微信超时 | 整数，1 至 30 秒 |
| 安全策略 | 来源限额不得低于账号限额；验证码冷却不得超过有效期；相关字段变化时重新校验 |

资料控件共用 `platform/profile-fields/validation.ts`，覆盖注册、管理员资料编辑和账号自定义资料。密码继续使用既有 Unicode 码点与 UTF-8 字节策略；手机号继续使用 E.164。配额的 GiB 输入和水印透明度保留合法小数，不能套用整数规则。

## 插件格式

| 插件 | 规则 |
| --- | --- |
| 敏感词 | 原词最多 128 个 UTF-16 单元；匹配归一后也必须非空且不超过相同上限。新增、编辑、CSV、粘贴导入使用相同归一规则；分类候选由服务端字典校验，类别长度按 64 个 Unicode 码点计算 |
| 本地化 | 文案键与命名空间使用既有正则，文案最多 2000 个 UTF-16 单元；翻译语言按 BCP 47 规范化，`en` 与 `EN` 等规范化后重复键直接拒绝，避免静默覆盖 |
| 支付 | 金额为整数分，范围 1 至 2147483647；支付主体最多 127 个 UTF-8 字节，退款原因最多 80 个 UTF-8 字节，均非空且无 NUL。中文与 emoji 按实际编码字节计数 |
| 工单反馈 | 继续使用已有标题、富文本、图片数量、回复长度及分类状态枚举限制；updatedAt 时间筛选显式声明为日期列 |
| MFA | 保留既有请求体、验证码、UUID 和操作原因规则，绑定、恢复与管理员重置继续执行各自状态机校验 |

字符数、Unicode 码点和 UTF-8 字节不能互换。JavaScript `string.length` 与 Java `String.length()` 都以 UTF-16 单元计数；支付等供应商按字节限制的字段必须使用 UTF-8 编码长度。

## 回归检查

新增规则至少覆盖有效边界、边界加一、可选空值、错误类型和中文或 emoji。提交校验失败时保留表单输入，修改为合法值后能够重试；服务端非法请求不得进入业务写入。

- `tests/data-format-validation.test.mjs`：资料格式、精确数字、日期和 SMTP。
- `tests/plugin-data-validation.test.mjs`：支付 UTF-8 字节、敏感词归一及中文边界，已接入默认 Node 测试发现。
- `RequestJsonBindingTest`：真实 MVC 绑定、错误状态、写入前拦截及共享读取器兼容。
- `PageRequestTest` 与 `PageFilterSqlTest`：分页、筛选类型、日期边界及实际 PostgreSQL 时间比较。
- `SensitiveWordInputValidationTest`、`LocalizationServiceTest`、`PaymentCoreServiceTest`：插件业务入口边界。

数据库测试使用专用 QA 数据库；浏览器交互、保存后刷新和服务健康检查分别验收。全局初始化仍只有 `B52__platform_initialization.sql`，格式校验优化不修改已发布插件迁移。
