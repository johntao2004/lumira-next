# 持久化邮件任务

当前提供内部存储、传输和调度消费者，尚未对用户开放发送入口。

MailDeliveryStore 的 enqueue 可以参加调用方事务。调用方负责授权、限流和审计，并为同一逻辑操作提供稳定 UUID；重复 UUID 保留首次内容和期限，不会覆盖或重新发送。收件人、主题、正文统一加密，并绑定任务 ID；完整 JSON 不超过 64 KiB，有效期最长一天。不保存 SMTP 密码副本，后续消费者在发送时加载当前配置。

| 状态 | 意义与后续处理 |
| --- | --- |
| PENDING | 达到计划时间后领取；超过有效期转 EXPIRED |
| LEASED | 已领取但未开始网络发送；两分钟租约，到期可重新领取 |
| SENDING | 即将/正在网络发送；租约到期转 UNCERTAIN，不能自动重发 |
| ACCEPTED | SMTP 已确认接受，不等于收件箱收到 |
| FAILED | 认证/配置失败，或达到五次尝试上限 |
| UNCERTAIN | 可能已发送，禁止自动重试 |
| EXPIRED | 超过任务有效期，不再开始新发送 |

领取通过 FOR UPDATE SKIP LOCKED 和原子更新完成，每次生成新令牌。读取内容、开始发送和完成更新均检查 ID/令牌/状态；旧领取者不能覆盖新状态。消费者必须先读取内容与配置，提交 beginSending 后才可调用网络传输。发送不能处于数据库事务中。

只有 CONNECTION_FAILED 自动回到 PENDING，以 60、120、240、480 秒等待后续尝试，总领取次数最多五次。认证失败和结果不确定不自动重试。进程崩溃时无法保证知道 SMTP 是否已接受，因此不宣称邮件恰好发送一次。过期恢复每批最多 1000 条，跳过其他进程持有的行锁。

MailDeliveryWorker 每两秒轮询，启动后十秒开始。每实例最多四个并发虚拟线程，每轮最多领取四条；水平扩展的排他性由数据库行锁与令牌提供。读取配置和内容后，开始状态与 mail.started 审计同事务提交，SMTP 网络操作随后进行；完成状态与结果审计也在同一事务。更新失败时保留原状态，不伪造接受结果。

单次网络尝试设置 60 秒中断期限，超时统一记录为 UNCERTAIN，即使底层因中断返回连接失败。凭据读取和数据库操作尚未纳入同一个绝对截止时间。未领取/已失效的任务不会调用传输；关闭应用会停止领取并中断活动工作线程。日志仅包含任务 ID 与异常类型，不输出收件人、正文、凭据或 SMTP 回复。

`GET /api/platform/mail-deliveries` 和 `/dashboard/mail-deliveries` 提供全局运维记录。接口要求全局 `platform:audit:read`，支持有界分页、任务 ID 子串搜索和精确状态筛选；数据与总数使用同一个可重复读事务。仅返回 ID、状态、次数、结果和时间字段，不读取或返回负载与租约令牌。页面复用 ResourceTable，支持手动刷新及十秒轮询；权限错误会隐藏缓存记录，临时服务错误保留记录并显示错误提示。

过期恢复返回实际变更的任务 ID 和状态，消费者将整批恢复与对应审计放在同一事务；审计失败会回滚状态，重复恢复不会重复记账。审计区分重新等待、过期、耗尽尝试和结果不确定。

本地集成测试将真实 PostgreSQL 加密队列、消费者、真实 TLS SMTP 传输与审计表串联，配置来源使用测试夹具。成功路径确认 SMTP 接受与两条审计；注入接受结果审计失败后，状态回滚为 SENDING，过期恢复为 UNCERTAIN 且只记录一次。独立数据库测试覆盖恢复审计失败回滚。未向外部投递。

尚待接入：人工处理不确定结果的操作权限、终态保留清理与账号验证/恢复生产者。当前不应通过直接修改数据库状态来重发邮件。
