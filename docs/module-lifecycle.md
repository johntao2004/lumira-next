# 模块生命周期

当前阶段：内部状态存储、管理接口和前端开关已接通，审计查询是首个经过端到端验证的可选模块。模块包登记、摘要幂等和激活/拒绝状态机已接入，但仅保存部署交接元数据；身份/平台管理为不可停用的核心模块，运行进程不会执行上传代码。

V42 已把服务端拥有的版本化导航树接入模块边界：树形与双层布局读取同一运行时快照，菜单权限和模块状态在后端过滤，管理员可管理自定义节点。V43 保证 PAGE 地址唯一，V44 让受限 componentKey 通过前端代码注册表解析；安全 PAGE slug 可解析到 Umi 动态路由，未注册组件时显示受控占位页，菜单数据不能凭空加载任意代码。V43 的反馈创建页面复用账号级草稿协议，不把权限或附件元数据写入草稿。V45 新增敏感词策略模块，词典管理、匹配快照和反馈阻断受同一模块状态约束。V46 新增运行时本地化模块，管理 API、公开 bundle、短 TTL 缓存和前端静态回退均受同一模块状态约束。V47 增加短信配置、加密投递队列和账号手机验证；这些公共能力仍由平台核心边界统一保护。审计保留由核心平台定时有界清理，登录拒绝事件复用账号安全审计。当前新增声明式模块包生命周期，用于部署交接，不把“登记包”扩大为任意插件执行。

## 契约

`PlatformModule` 描述随程序部署的模块 ID、名称、代码版本、依赖和 required 标志。身份及平台管理是 required 模块；required 模块只能依赖 required 模块，避免核心依赖被默认停用。注册时拒绝非法/过长 ID、重复 ID、缺失依赖、环和错误核心依赖。

`ModuleStateStore` 只对当前注册模块返回状态。required 模块始终启用且不能停用；尚无状态的可选模块默认停用、状态版本为 0。数据库中存在但当前部署未注册的模块记录保留，不作为运行能力返回。代码版本与状态版本是不同概念；当前不支持上传或热加载任意代码。

## 变更一致性

- 变更携带期望状态版本、操作者和变更原因。未知模块、非法输入、过期版本、核心模块停用和依赖冲突明确拒绝。
- 单个数据库事务先取得图级 advisory lock 481027，再读取最新状态、验证提议后的完整依赖图；不能启用依赖未启用的模块，也不能停用仍有启用模块依赖的模块。
- 实际变更同时写入状态、修订历史和公共审计。审计失败导致全量回滚；同版本无变化请求不增加修订或审计。此行为不能替代 HTTP 幂等键。
- V30 存储当前状态与每次修订。未删除模块数据，不执行数据库卸载。

## 后续适配要求

管理适配层必须在同一事务中先调用 AdministrationGuard 检查模块写权限及全局管理范围，锁顺序为 481026 → 481027。内部存储不负责登录鉴权，也不直接暴露为通用写 API。

接入前必须定义每个可选模块拥有的页面/API/后台任务/跨模块调用边界，令后端执行状态约束，前端根据同一能力状态隐藏入口和阻止直达。需明确已开始请求和后台任务的停用语义；只加按钮或只隐藏菜单不算完成。模块安装升级还需要代码清单兼容性、迁移版本和多实例一致性策略。

## 验证

真实 PostgreSQL 测试覆盖默认状态、核心与依赖保护、过期版本、无变化请求、未知模块、审计失败回滚、相同版本竞争，以及不同模块并发变更不会破坏依赖图。测试使用独立 schema，结束清理，不修改当前模块状态。

完整后端 clean verify：当前 252 项测试，失败/错误/跳过均为 0。此结果覆盖内部状态机制、声明式模块包状态机和当前平台适配，不证明生产容量、故障切换或任意插件代码的动态加载。

## 管理接口

- `GET /api/platform/modules` 要求 `platform:modules:read`，保留 id/name/version/dependencies，并返回 required/enabled/stateVersion。version 是随代码部署的版本，stateVersion 是启停状态版本。
- `PUT /api/platform/modules/{id}/state` 要求 `platform:modules:write`、CSRF 和全局范围。请求为 enabled/version/reason，最多 4096 字节；操作者来自认证上下文。事务内先重查权限与全局范围，再进入状态存储。
- 未注册模块返回 404；核心保护、依赖冲突和旧版本返回 409；缺字段、无原因或非法版本返回 400，请求体超过字节上限返回 413。无变化操作返回原状态、不追加审计。
- 新权限加入角色权限目录、首次管理员引导及 V31 现有管理员迁移。SELF/ORGANIZATION/SUBTREE 写权限不授予全局模块控制。

### 声明式模块包生命周期

- `GET /api/platform/modules/packages` 和 `GET /api/platform/modules/{id}/packages` 要求 `platform:modules:read`；模块页的“模块包”抽屉复用 `ResourceTable`、`PlatformDrawer`、`FormDrawer`、React Query 和八语言目录。
- `POST /api/platform/modules/packages` 要求 `platform:modules:write`、CSRF 和全局范围，最多 65,536 字节。请求包含 `manifest` 与登记原因；服务端校验模块 ID、SemVer、schema/API 版本、依赖、权限、页面、HTTPS/OCI/S3 制品地址和 64 位 SHA-256，按规范化 JSON 计算 manifest 摘要。
- 相同 `moduleId + packageVersion + artifactDigest` 的重复登记是幂等的；拒绝过的相同摘要不会被重新登记。`STAGED` → `ACTIVE`/`REJECTED` 需要携带当前 `revision` 和原因，数据库图锁 `481027` 加行锁保证并发状态不会互相覆盖。
- 激活前必须找到当前静态代码注册、包版本与部署版本完全一致、依赖集合一致且依赖已启用；未注册模块、版本/依赖冲突和过期 revision 分别返回结构化 409。激活会把同模块旧 ACTIVE 标为 `SUPERSEDED`，不会删除历史元数据。
- 包表只保存 manifest、引用、摘要、状态、版本和审计关联；服务端不下载、不解压、不反射加载、不执行上传制品。真正的制品签名/扫描、数据库变更、滚动发布、对象存储和多实例一致性由部署流水线完成。

当前仍需完成可选模块拥有的端点/任务/页面清单及执行约束、部署流水线和生产故障切换验收；模块包登记接口本身不代表动态代码安装已经完成。

管理适配验证：完整 clean verify 171 项通过；V31 运行版本真实 HTTP 回归通过读写分离、SELF/ALL 范围、CSRF、核心保护、版本/请求边界、无变化审计及即时撤权。旧登录/模块读取/用户分页回归也通过。

## HTTP 归属与访问检查

控制器或具体方法使用 `@ModuleEndpoint("module-id")` 声明归属，方法声明优先。启动时扫描已解析的 MVC handler，未声明归属或声明的模块不存在时拒绝启动。当前全部 48 个 Controller 已声明 identity、platform 或对应可选模块归属；后续新增接口必须先补齐归属才能启动。

ModuleAccessInterceptor 在 Spring Security 过滤链之后检查实际 handler；required 模块不增加状态查询，可选模块每次读取共享数据库状态，无状态或停用时返回 503/moduleUnavailable。未知模块运行时也拒绝访问。

该检查提供请求进入时的状态判断，不中止已经开始的请求，也不控制后台任务、服务内调用或数据库迁移。可选模块正式开放前必须明确这些边界和前端能力同步。当前运行实例注册两个 required 模块及 audit-console 可选模块。

访问拦截验证：175 项完整 clean verify 通过，随后新增的 MVC 请求链测试与拦截器专项五项全部通过。启动验证器在当前真实运行实例完成，尚未以已注册的可选功能模块做端到端停用验收。

## 首个可选模块：审计查询

`audit-console` 拥有操作审计页面及 `GET /api/platform/audit`（含全部分页/搜索）。依赖 platform，无后台任务。核心 AuditRepository 和审计写入、个人安全记录、登录行为不属于此查询模块，停用后继续正常工作。

V32 显式保留迁移前已经启用的审计查询，写入状态、修订和迁移审计；不是将所有新可选模块改为默认启用。启停不删除审计数据。

`/api/auth/me` 提供 enabledModules，导航和页面使用同一模块归属/权限交集判断；直接进入已停用页面显示模块不可用。模块管理复用 ResourceTable/FormDrawer/API/八语言，变更必须填写原因并携带版本，核心模块无停用按钮。

当前标签页写入后刷新模块和身份缓存；同源标签页通过 BroadcastChannel 更新，身份查询另在聚焦及前台每 30 秒刷新。来自其他浏览器或直接 API 的变更可有最长一个刷新周期的菜单延迟；后端状态约束立即生效，moduleUnavailable 响应也触发能力刷新。

真实 HTTP 验证了停用、恢复、已有会话阻断、能力变化及持续审计写入。浏览器验证了管理开关、跨标签页更新、直达/刷新拒绝、重新启用恢复和 390px 抽屉范围，截图已复核。测试恢复原启用状态，变更审计保留。没有把这一结果扩大为所有模块或生产多实例生命周期验收。

## 模块变更历史

`GET /api/platform/modules/{id}/history?page=1&pageSize=20` 返回版本倒序的 id/version/enabled/changedBy/changeReason/createdAt，分页上限 100。历史与模块 ID 隔离；未注册模块 404，尚无修订的已注册模块返回空页。计数和分页在同一可重复读事务快照中执行。

历史需要模块读取权限及全局范围，SELF 等局部读取角色可查看模块清单，但不能查看全局变更原因和操作者。模块页仅向有全局读取权限的用户显示历史入口，复用 PlatformDrawer/ResourceTable 和八语言文案。历史接口属于核心管理模块，审计查询停用时仍可使用。

真实数据库测试覆盖 105 条修订的分页、排序和模块隔离；真实 HTTP 回归覆盖读取权限、SELF/ALL 切换、空记录、未注册模块与分页边界。桌面历史打开、刷新、关闭及 390px 抽屉边界与内部横向滚动浏览器回归通过；手机截图已复核。生产构建通过。
