# Lumira 插件

这是平台独立插件的源码与发布目录。`feedback`、`localization`、`sensitive-words`、`mfa`、`diffuse-avatar` 分别提供工单反馈、运行时本地化、敏感词策略、TOTP 二次认证和弥散渐变头像。`payment-core` 提供扫码支付配置、订单和退款状态机；`wechat-pay` 与 `alipay-pay` 是可独立启停的渠道适配器；`sdk` 为共享开发契约。支付安装、安全和接入边界见 [支付插件说明](../docs/payments.md)。

## 构建与安装

使用 Node 24、pnpm 10.33.0 和 JDK 25，在仓库根目录运行 `pnpm plugins:build`，或 `pnpm plugins:build feedback`。工具先编译宿主 SDK，再编译插件后端和前端，生成 `plugins/<id>/dist/<id>-<version>.lumira-plugin.zip`。开发源码纳入 Git，dist 为可重建的编译产物。

在平台模块 → 可管理模块点击“导入插件”，选择安装包，再点击“安装插件”，查看依赖处理清单后确认。导入只是准备安装包；健康检查通过后才开放插件功能。

卸载检查所有已安装插件的反向依赖，清理闲置自动依赖，保留明确安装的依赖和所有核心模块。业务数据、配置、源码、发布包保留。部署副本位于 `.runtime/plugins/`；不要手工修改运行目录。

首次启动新架构前必须构建此次部署要启用的插件安装包。平台继承原有模块状态、授权和数据，之后重启从安装目录恢复，不再依赖源码目录。

权限最终化版本要求先完成宿主 B52 初始化；该基线提供当前权限目录、归一函数和数据库归档表。插件仍按各自的 Flyway 历史升级，已发布插件脚本保持不变。B52 宿主上全新安装相关权限插件时，反馈、本地化和敏感词的旧 `V2` 只按原版本、脚本和校验和登记，不执行旧 SQL；已有插件迁移历史的升级继续执行待处理的 `V2` 以转换旧授权。MFA 待执行的旧 `V6` 始终按原校验和登记但不运行，避免重放管理员引导授权。追加的插件 finalizer 会处理符合条件的旧聚合权限并调用 B52 提供的归一函数；缺少该函数时安装迁移失败。不要通过修改旧插件迁移或手工写权限行绕过该步骤。插件版本号、前后端描述符与依赖锁定值应保持一致。
